# 서울·경기·인천 정비사업·개발계획 데이터 연동 우선순위

- 작성일: 2026-08-03
- 대상 서비스: 땅뷰(LandView)
- 대상 지역: 서울특별시, 경기도, 인천광역시
- 목표: 공식 데이터를 이용해 정비사업 및 개발계획 예정구역을 지도에 통합 표시

## 1. 결론

땅뷰는 경쟁 서비스의 장점을 다음과 같이 결합한다.

- 재개발닷컴: 정비사업 단계, 타임라인, 구역 내 실거래가 중심
- 네이버 부동산·다울지도: 개발지구를 넓은 지도에서 빠르게 탐색
- 땅뷰: 공식 데이터만 사용하면서 정비사업, 개발지구, 필지, 토지이용계획, 실거래가를 한 화면에서 연결

경쟁 서비스의 비공개 API나 데이터를 수집하지 않고 화면 구성과 기능만 참고한다.

사용자 화면에서는 데이터 출처별로 색상이나 레이어를 구분하지 않는다. 대신 `정비사업`, `공공택지`, `도시개발`, `교통개발` 같은 사업 종류와 `후보`, `공람`, `지정`, `착공`, `준공` 같은 진행 상태로 구분한다.

다만 중복 제거, 오류 수정, 최신 데이터 선택을 위해 내부 DB에는 원본 출처, 원본 ID, 기준일, 고시번호를 반드시 보관한다.

### 1.1 표시 범위 재정의

`정비구역`만 표시하면 정비구역 지정 전 후보지와 별도 법률에 따른 사업이 누락된다. 땅뷰의 정비·개발사업 범위는 다음과 같이 확장한다.

| 화면 사업유형 | 포함 범위 | 데이터 모델 원칙 |
|---|---|---|
| 재개발 | 주택정비형·도시정비형 재개발, 정비구역 지정 전 후보지 | 기본 사업유형으로 저장 |
| 재건축 | 공동주택 재건축, 정비구역 지정 전 안전진단·기획 대상 | 기본 사업유형으로 저장 |
| 신속통합기획 | 서울시 신속통합기획 재개발·재건축 | 별도 사업을 만들지 않고 기존 사업의 `fast_track_planning` 태그로 저장 |
| 공공재개발·공공재건축 | LH·SH·GH 등이 참여하는 공공 정비사업 | 기본 사업유형과 `public_led` 태그를 함께 저장 |
| 모아타운 | 소규모주택정비 관리지역과 후보지 | 상위 관리지역 프로젝트로 저장 |
| 모아주택 | 모아타운 안팎의 가로주택정비 등 개별 사업 | `parent_project_id`로 모아타운과 연결 |
| 소규모주택정비 | 가로주택, 자율주택, 소규모재개발·재건축 | 세부 사업유형 유지 |
| 도심 공공주택 복합사업 | 후보지, 예정지구, 복합지구, 사업승인 지구 | `public_housing_complex` 유형과 법적 단계 저장 |
| 재정비촉진사업 | 재정비촉진지구와 지구 내 촉진구역 | 상위 지구와 하위 구역을 계층 연결 |
| 역세권·준공업지역 개발 | 역세권 활성화, 역세권 장기전세, 준공업지역 복합개발 등 | 제도별 태그를 유지하고 확정 단계와 후보 단계를 구분 |
| 도시재생 | 도시재생법상 활성화지역·사업 | 정비사업과 섞지 않고 별도 유형으로 저장 |

후보지·기획대상·법정구역은 같은 색으로 뭉뚱그리지 않고 `후보 → 계획수립 → 심의·공람 → 구역지정 → 조합·사업시행 → 착공 → 준공` 단계로 구분한다. 지도 집계에서는 동일 사업의 태그를 별도 건수로 중복 계산하지 않는다.

## 3. 광역·기초단체 정비사업 데이터

정비사업의 사업단계와 일정은 광역·기초단체 공식 데이터를 우선 사용한다.

### 3.1 인천광역시

인천은 현재 연동 가능한 데이터 구성이 가장 명확하다.

#### 일반 정비사업

- 데이터: [인천광역시 도시 및 주거환경 정비사업 추진현황](https://www.data.go.kr/data/15055212/fileData.do)
- 주요 항목: 구역명, 위치, 면적, 사업유형, 진행단계
- 현재 반영본: 2026-05-31 기준 144건
- 갱신주기: 월간
- 이용조건: 이용 제한 없음

#### 소규모주택정비

- 데이터: [인천광역시 소규모주택정비 추진현황](https://www.data.go.kr/data/15072776/fileData.do)
- 주요 항목: 가로주택, 소규모재건축·재개발, 구역명, 위치, 면적, 추진단계, 조합원 수, 토지등소유자 수, 건축심의일, 사업시행계획인가일, 관리처분계획인가일, 착공일
- 현재 반영본: 2026-04-27 기준 111건
- 갱신주기: 월간
- 이용조건: 이용 제한 없음

인천 일반 정비사업과 소규모주택정비 데이터는 1차 구현 대상으로 사용한다. 공공데이터포털의 월간 CSV를 원본 그대로 보관하고 `scripts/convert-incheon-maintenance.py`로 공통 모델에 맞춘 웹용 JSON을 생성한다. 화면에 표시할 때 대표자명 등 개인 식별 가능성이 있는 항목은 제외한다.

VWorld 도시계획 경계와 인천 추진현황은 정규화한 구역명으로 결합한다. 일치 후보가 하나일 때만 사업단계를 표시하며, 불일치하거나 후보가 여러 개인 경우 임의로 연결하지 않는다. 따라서 경계에 추진현황이 표시되지 않더라도 사업이 없다는 뜻은 아니다.

원본 위치를 VWorld 주소검색으로 확인해 255건 중 180건에 대표 좌표를 연결했다. 주소가 없거나 `일원`, 도로 구간, 잘못 입력된 값처럼 단일 좌표를 신뢰하기 어려운 75건은 임의 좌표를 만들지 않고 속성 데이터로만 유지한다. 대표 좌표는 사업구역 경계를 뜻하지 않는다.

새 공식 파일을 반영할 때는 다음 형식으로 변환한다.

```powershell
python scripts/convert-incheon-maintenance.py `
  --general "경로/인천_일반정비사업.csv" `
  --small "경로/인천_소규모주택정비.csv" `
  --general-base-date 2026-05-31 `
  --small-base-date 2026-04-27 `
  --output public/data/incheon-maintenance-projects.json

python scripts/geocode-incheon-maintenance.py `
  --input public/data/incheon-maintenance-projects.json `
  --output public/data/incheon-maintenance-projects.json `
  --env-file .env
```

### 3.2 서울특별시

서울 정비사업의 기준 포털은 [정비사업 정보몽땅](https://cleanup.seoul.go.kr/)이다.

다만 서울 열린데이터광장에서 제공하던 다음 핵심 API는 현재 종료 상태다.

- [서울시 재개발·재건축 정비사업 현황](https://data.seoul.go.kr/dataList/OA-2253/S/1/datasetView.do)
- [서울시 건설 정비사업 추진 경과 정보](https://data.seoul.go.kr/dataList/OA-2254/S/1/datasetView.do)

서울시는 OA-2254의 공식 대체 데이터로 [OA-22856 서울특별시 도시정비사업 통계](https://data.seoul.go.kr/dataList/OA-22856/S/1/datasetView.do)를 지정했다. 이 데이터는 분기 단위 엑셀 파일로 추진단계와 지정일 등을 제공하며 공공누리 1유형이다.

2026년 3월 31일 기준 파일은 472건이다. 땅뷰는 4행 병합 헤더와 엑셀 날짜 일련번호를 검증해 전체를 정규화했고, 공식 주소가 확인된 414건을 대표 위치로 지도에 연결했다. 유형별 건수는 주택정비형 재개발 153건, 도시정비형 재개발 132건, 공동주택 재건축 117건, 아파트지구 재건축 42건, 단독주택 재건축 28건이다. 대표 위치는 경계 폴리곤이 아니므로 탐색용으로만 표시한다.

```powershell
python scripts/convert-seoul-maintenance.py `
  --input <서울시-OA-22856-엑셀-경로> `
  --base-date 2026-03-31 `
  --output public/data/seoul-maintenance-projects.json

python scripts/geocode-maintenance-projects.py `
  --input public/data/seoul-maintenance-projects.json `
  --output public/data/seoul-maintenance-projects.json `
  --region-name 서울특별시 `
  --env-file .env
```

서울 열린데이터광장의 [OA-22712 서울시 도시계획사업 현황(서울플랜+) 공간정보](https://data.seoul.go.kr/dataList/OA-22712/F/1/datasetView.do)는 재개발·재건축뿐 아니라 신속통합기획, 모아타운 등 서울시 도시계획사업을 한 SHP에 포함하므로 공간 범위는 가장 좋다. 다만 현재 공공누리 제4유형(상업적 이용·변경 금지)이므로 웹용 변환·재배포에 바로 사용하지 않는다. 서울시에 상업 서비스 내 지도 표시와 좌표 변환 허용 여부를 서면으로 문의하고, 허용되면 서울 통합 공간 주 데이터로 승격한다.

[서울시 신속통합기획 추진현황](https://news.seoul.go.kr/citybuild/plan-progress)은 2026년 6월 기준 309개 대상지를 집계하지만 제4유형이다. [서울시 모아타운 추진현황](https://news.seoul.go.kr/citybuild/moa-housing-town/policy/status)은 2026년 3월 말 기준 132개 관리지역을 제공하지만 역시 제4유형이다. 두 페이지는 현재 건수·단계 교차검증과 누락 확인에만 사용하고 운영 DB로 복제하지 않는다.

도심 공공주택 복합사업은 전국 단일 최신 개방 목록을 전제로 하지 않고 국토교통부·LH와 지역 공기업의 공식 사업별 데이터를 합친다. 현재 연결한 국토교통부 `LSMD_CONT_UD620` 수도권 파일에는 명칭·비고 기준 14개 도심 공공주택 복합지구 경계가 포함되어 있으며 굴포천역 남측 지구도 포함된다. [인천광역시 굴포천역 남측 도심 공공주택 복합지구 편입지번](https://www.data.go.kr/data/15160356/fileData.do)은 373개 필지를 제공하므로 해당 경계의 편입 필지 교차검증에 사용한다. 아직 지구로 지정되지 않은 후보지는 국토교통부·LH·지역 공기업의 공식 발표 자료를 별도 수집하고, 후보지·예정지구·복합지구·사업승인 등 법적 단계를 보존한다.

따라서 다음 순서로 데이터를 확보한다.

1. OA-22856을 정비사업 속성 주 데이터로 정기 반영
2. OA-22712의 상업적 지도 이용·좌표 변환 허용을 서울시에 문의
3. 신속통합기획·모아타운은 이용 허락을 받은 공식 목록 또는 별도 제공 데이터를 태그와 상위 관리지역 구조로 반영
4. 정비사업 정보몽땅으로 최근 사업단계 교차검증
5. 서울 도시계획 공간정보, VWorld, 고시 지형도면에서 법적 경계 확보
6. [OA-20281 서울시 도시계획 정비사업 현황](https://data.seoul.go.kr/dataList/OA-20281/A/1/datasetView.do)은 공공누리 4유형의 상업적 이용·변경 제한을 확인한 후 보조 사용
7. 부족한 항목은 서울시에 공공데이터 제공신청

[도시재생종합정보체계](https://www.city.go.kr/portal/notice/opensys/contents01/link.do)는 OpenAPI·SHP·CSV를 제공하지만 도시재생법상 도시재생사업을 중심으로 한다. 재개발·재건축의 대체 데이터로 취급하지 않고 `urban_regeneration`이라는 별도 사업유형으로 연동 여부를 검토한다.

서울부동산정보광장은 필지별 부동산 종합정보의 확인 창구로 사용하되 정비사업 통합 수집원으로 사용하지 않는다.

정비사업 정보몽땅의 화면이나 비공개 요청 주소를 임의로 크롤링하는 방식은 이용조건과 구조 변경 위험이 있으므로 운영 데이터로 사용하지 않는다.

### 3.3 경기도

경기도는 2025년 6월부터 [경기도 정비사업 온누리시스템](https://www.gg.go.kr/onnuri/)을 운영하고 있다. 구현 전 온누리시스템의 정식 OpenAPI 또는 대량 파일 제공 여부를 먼저 확인한다.

확인 항목은 다음과 같다.

- 사업장 마스터와 공식 사업 ID
- 사업단계와 수정일
- 주소와 사업구역 경계
- 서울·경기·인천 서비스에서의 저장·가공·상업적 이용 가능 여부
- 인증방식, 호출량과 갱신주기

공식 API가 있고 데이터 범위가 충분하면 경기도 주 데이터로 사용한다. API가 없거나 구역·시군별 정보가 불완전하면 온누리시스템은 교차검증용으로 사용하고 [경기데이터드림 OpenAPI](https://data.gg.go.kr/portal/openapi/usagePage.do)와 각 시·군 공식 데이터를 함께 사용한다.

권장 구축 순서는 다음과 같다.

1. 부천·광명·안양
2. 성남·하남·과천
3. 고양·남양주·의정부
4. 수원·용인·군포·의왕
5. 나머지 시·군

각 시·군별 응답 형식은 공통 정비사업 모델로 변환한다. 지자체가 서로 다른 표현을 사용하더라도 화면에서는 다음 단계로 통일한다.

```text
후보지 → 입안·공람 → 구역지정 → 추진위원회 → 조합설립
→ 사업시행인가 → 관리처분 → 착공 → 준공
```

## 4. 공공주택지구 파일 연동

택지정보 OpenAPI는 인증키 발급이 불가능하므로 운영 연동 대상에서 제외한다. 신도시·공공주택 경계는 국토교통부가 제공한 `LSMD_CONT_UD620` SHP 파일을 핵심 데이터로 사용한다.

### 연동 원칙

- 서울·경기·인천 파일만 사용하며 원본 ZIP은 수정하지 않는다.
- 변환 스크립트에서 CP949 속성문자를 읽고 EPSG:5186 경계를 EPSG:4326으로 변환한다.
- 변환 결과는 정적 GeoJSON으로 배포해 별도 API 키나 Vercel 함수 없이 표시한다.
- 새 파일을 받으면 같은 스크립트를 다시 실행하고 변경 건수와 기준월을 검증한 뒤 배포한다.
- 화면에는 원천 파일이 제공하는 구역명, 고시일, 면적, 행정구역 코드, 고시 식별자만 표시한다.

### 현재 사용할 속성자료

- `ALIAS`: 구역명
- `REMARK`: 비고 및 보조 구역명
- `NTFDATE`: 고시일
- `COL_ADM_SE`: 행정구역 코드
- `MNUM`: 고시·도면 식별자
- 도형에서 계산한 구역 면적

### 사용할 공간자료

- `LSMD_CONT_UD620_서울_202607`
- `LSMD_CONT_UD620_경기_202607`
- `LSMD_CONT_UD620_인천_202607`

현재 파일에는 사업단계, 시행자, 계획 세대수, 계획 인구, 토지이용계획도가 없으므로 화면에서 추정하거나 빈 값을 만들지 않는다. 이 정보는 향후 다른 공식 파일이나 정식 API를 확보했을 때 별도 결합한다.

VWorld 2D 데이터 API의 다음 레이어는 보완 자료로 검토한다.

- `lhzone` / `LT_C_LHZONE`: 사업지구 경계
- `lhblpn` / `LT_C_LHBLPN`: 택지 토지이용계획도

[국토교통부 사업지구경계도 API](https://www.data.go.kr/data/15058609/openapi.do)는 혁신도시, 택지개발예정지구, 신도시 등의 공간 경계를 제공한다. [국토교통부 토지이용계획도 API](https://www.data.go.kr/data/15057876/openapi.do)는 사업지구 안의 주택건설용지와 공공시설용지 계획을 제공한다.

땅뷰 상세화면에는 현재 확보한 파일 범위 안에서 다음 항목을 우선 노출한다.

- 사업지구명
- 사업유형
- 서울·경기·인천 지역 구분
- 고시일
- 행정구역 코드
- 고시·도면 식별자
- 도형에서 계산한 전체 면적
- 비고
- 사업지구 경계

`scripts/convert-development-projects.py`가 서울·경기·인천 자료만 검증해 `public/data/development-projects-capital-region.geojson`으로 저장한다. 지도는 이 정적 파일을 한 번 읽은 뒤 현재 화면과 겹치는 구역만 표시한다.

새 공식 파일을 반영할 때는 다음 형식으로 변환을 다시 실행한다.

```powershell
python scripts/convert-development-projects.py `
  "경로/LSMD_CONT_UD620_서울.zip" `
  "경로/LSMD_CONT_UD620_경기.zip" `
  "경로/LSMD_CONT_UD620_인천.zip" `
  --output public/data/development-projects-capital-region.geojson
```

### 현재 연결한 정비·도시개발·택지개발 구역

공공주택지구 파일과 별도로 VWorld `LT_C_UPISUQ161` 도시계획 공간정보를 지도 영역 단위로 조회한다.

- 정비구역: 구역명에 `정비`, `재개발`, `재건축`이 포함된 도형을 조회하고 원본 ID로 중복 제거
- 도시개발구역: 구역명에 `도시개발`이 포함된 도형 조회
- 택지개발지구: 구역명에 `택지개발`이 포함된 도형 조회
- 화면 표시: 구역명, 구역 유형, 지역, 면적, 도시계획 분류, 집행 구분, 행정구역 코드, 고시 식별자

이 레이어는 공식 도시계획 도형을 명칭 조건으로 선별한 탐색 자료다. 정비사업의 실제 진행 단계와 조합·인가 정보는 광역·기초단체 정비사업 데이터로 별도 보강한다.

전국 정비구역 SHP 파일 데이터도 확인했으나 현재 공공누리 제4유형(상업적 이용·변경 금지)으로 안내되어 웹용 변환·재배포 자료에는 사용하지 않는다. 별도의 이용 허락을 확보하거나 이용 제한 없는 정식 API가 확인되기 전까지는 VWorld 조회 경계와 지자체 추진현황 대표 위치를 조합한다.

## 5. 국토교통부 토지이용계획정보 연동

LURIS는 현재 토지이음 체계로 통합되어 있다. 실제 시스템 연동은 [국토교통부 토지이용계획정보 WMS/WFS/속성정보](https://www.data.go.kr/data/15123973/openapi.do)를 사용한다.

이 데이터는 토지이용계획정보와 연속지적도를 결합한 필지 기반 공간정보이며 실시간 갱신되고 이용 제한이 없다.

토지이용계획정보는 사업 추진단계의 기준 데이터가 아니라 다음 내용을 확인하는 보조·검증 데이터로 사용한다.

- 클릭한 필지가 정비구역에 포함되는지 확인
- 재정비촉진지구 포함 여부
- 공공주택지구·도시개발구역 포함 여부
- 용도지역·용도지구
- 지구단위계획구역
- 토지이용 규제와 행위제한
- 정비사업 포털 데이터의 법적 구역 지정 상태 교차검증

정비사업 포털에서 `사업단계`를 가져오고, 토지이용계획정보로 `법적 구역 지정`을 확인하는 구조로 구현한다.

사용자 화면에는 출처별 구분을 표시하지 않더라도 내부에서는 다음 항목을 보관한다.

```text
area_m2

operator_name
geom
notice_no
notice_date
official_url
source_provider
source_dataset
source_record_id
source_updated_at
collected_at
match_confidence
```

### 중복 통합 기준

1. 광역·기초단체 공식 사업 ID가 같으면 동일 사업으로 처리
2. 사업 ID가 없으면 지역, 정규화된 구역명, 주소를 비교
3. 공간 경계가 있으면 폴리곤 중첩률을 추가 비교
4. 공식 고시번호가 같으면 동일 사업으로 확정
5. 자동 매칭이 불확실하면 관리자 검수 대상으로 분리

### 데이터 충돌 우선순위

1. 가장 최근의 공식 결정·지형도면 고시
2. 광역·기초단체 정비사업 포털
3. 택지정보시스템의 최신 지구 이력
4. 토지이용계획정보의 현재 법적 지정 상태
5. 국토교통부 연간 통합 데이터

자동 수집이 쉽다는 이유로 데이터의 법적 정확성 우선순위를 높이지 않는다. 수집 방식은 별도로 다음 순서를 적용한다.

### 자동 수집 우선순위

1. 공식 OpenAPI
2. 공식 CSV·SHP·엑셀 파일
3. 공식 수동 다운로드 자료
4. 공식 포털 웹 화면을 이용한 교차검증

포털의 비공개 요청 주소나 화면 구조에 의존하는 크롤링은 운영 수집 방식으로 사용하지 않는다.

9. 구역 내부 실거래가와 필지·건축물 정보 결합
10. 고시·공람·후보지 데이터 추가
11. 도로·철도 개발계획 추가

## 12. 필요한 인증키·신청 항목

| 항목 | 용도 |
|---|---|
| VWorld 인증키 | 토지이용계획정보, 사업지구경계도, 토지이용계획도 |
| 공공데이터포털 서비스키 | 향후 지자체 정비사업 OpenAPI 사용 시 필요. 현재 인천 월간 CSV 반영에는 불필요 |
| 경기데이터드림 인증키 | 경기도·시군 정비사업 데이터 |
| 서울 열린데이터광장 인증키 또는 데이터 제공 승인 | 서울 정비사업 관련 대체 데이터 |

실제 구현에 착수하기 전 각 서비스의 현재 승인 상태, 일일 호출량, 이용조건을 다시 확인한다.
